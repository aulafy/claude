## Before you start

Running a local model has three different moments: preparing the program, getting a response and checking whether it fits your task. Do not confuse the first “hello” with a complete evaluation. In this practice you will use fictional text and a test folder.

## 1. Prepare a reversible installation

Before downloading anything, note the program, version, installer source, expected storage and where its files will live. Read the chosen tool’s official documentation. Do not run a script you do not understand or grant administrator access out of habit.

Use a test folder separate from personal documents. If the installation offers network, telemetry or folder-access options, read them before accepting. Do not put keys or private data in a sample configuration.

## 2. Check that it starts

After installing, run the smallest test:

```text
Input: write three sentences about a fictional library.
Boundary: use no data outside this request.
Expected result: a short answer that keeps all three facts.
Record: version, approximate time and visible errors.
```

Seeing a response shows that the program can start a session. It does not yet show that it keeps facts, is fast or fits a real document.

## 3. Check the task

Repeat the case with a reference text and a check table. Mark whether the response keeps every fact, adds information, refuses, or runs out of resources. Keep the observed result, not a promise about what it should do.

If something fails, reduce the input size and change one variable at a time. A slow answer may be fine for study but not for customer support. A fluent answer can still be wrong.

## 4. Clean up and decide

Delete the test folder only after checking what it contains and confirming you do not need the record. Keep the version and observed limits if you will repeat the installation. If you cannot explain where data remains or what connections exist, stop before using real information and request technical review.

## Your result

You are done when you can distinguish a correct installation, a working run and a useful result, with a test you can repeat or delete. Local AI may offer more control, but it still requires system maintenance, file protection and checks after updates.

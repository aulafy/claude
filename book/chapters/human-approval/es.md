## Antes de empezar

Una casilla de «aprobar» no convierte una revisión en segura. La persona debe saber qué está aprobando, con qué fuente, qué permisos tiene la acción y qué ocurre si rechaza el resultado. En esta práctica trabajarás con un flujo ficticio y sin acciones externas.

## 1. Define el punto de aprobación

El flujo prepara un aviso para el club de lectura. La aprobación ocurre después de crear el borrador y antes de guardarlo en una carpeta compartida o enviarlo:

```text
Fuente -> borrador -> comprobación de hechos -> revisión humana -> acción permitida
                                                   |
                                             rechazo/parada
```

El revisor debe poder ver la fuente, el borrador, los datos añadidos y los permisos que se usarían. «Revisado por una persona» no es suficiente si no se define qué comprobó.

## 2. Escribe una lista de aprobación

Usa una lista breve y concreta:

| Comprobación | Decisión posible |
| --- | --- |
| La salida responde a la tarea | Aprobar o devolver |
| Cada hecho aparece en la fuente | Aprobar o rechazar |
| No hay datos personales innecesarios | Aprobar o eliminar |
| El destinatario y la acción son correctos | Aprobar o detener |
| El permiso coincide con la tarea | Aprobar o detener |

La aprobación debe referirse a una revisión concreta del borrador. Si el texto cambia después, hay que revisarlo de nuevo. No uses una aprobación antigua para autorizar una versión nueva.

## 3. Practica aprobar y rechazar

Revisa dos borradores ficticios. El primero conserva la hora y la sala de la fuente. El segundo añade cinco plazas y una fecha de inscripción que no constan. Aprueba el primero solo si la lista está completa; devuelve el segundo con este motivo:

```text
Rechazado: contiene dos datos sin respaldo en la fuente.
Siguiente paso: retirar ambos datos y volver a comprobar todo el borrador.
Acción externa: detenida.
```

No reemplaces el motivo por «la IA se equivocó». Un registro útil explica qué dato falló y qué debe ocurrir a continuación.

## 4. Diseña la parada

La parada debe conservar la entrada, el borrador rechazado, la fuente y el motivo, sin ejecutar el envío. Una persona responsable decide si se corrige, se archiva o se descarta según las reglas de su organización.

Prueba también una pérdida de conexión o una doble solicitud de aprobación. El resultado seguro es esperar o marcar el estado como pendiente, no ejecutar dos veces. Una automatización responsable puede ser más lenta porque hace visible una decisión importante.

## Tu resultado

Has terminado cuando puedes señalar el punto de aprobación, los criterios, la identidad o rol de quien revisa, el registro de la decisión y la acción de recuperación. La revisión humana no es un botón decorativo: es una frontera de responsabilidad.
